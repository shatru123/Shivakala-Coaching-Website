Shivakala Classes SmarterASP Deployment Guide

This guide covers the live deployment setup for the Shivakala Coaching website on SmarterASP.NET with SQL Server, a separate Node.js WhatsApp sidecar, and GitHub Actions based deployment.

Main Site: shivkalaclasses.com WhatsApp Sidecar: wa.shivkalaclasses.com Database: SmarterASP SQL Server Branch: main

1. Deployment Overview

The application is deployed as two separate web apps so the ASP.NET MVC site stays clean while the WhatsApp bridge runs independently on a Node.js subsite.

Main Website

  • Hosts the public website, admin portal, teacher portal, and parent portal.
  • Uses ASP.NET Core and SQL Server.
  • Primary URL: https://shivkalaclasses.com

WhatsApp Sidecar

  • Runs the Node.js service for QR login and WhatsApp broadcast.
  • Separate subsite to avoid mixing app runtimes.
  • Primary URL: https://wa.shivkalaclasses.com

4. Server App Settings

After the first publish, place this content into the deployed site1/appsettings.Production.json.

{
  "Database": {
    "Provider": "SqlServer"
  },
  "ConnectionStrings": {
    "SqlServer": "Data Source=SQL8002.site4now.net;Initial Catalog=db_aca3e8_shivkalaclasses;User Id=db_aca3e8_shivkalaclasses_admin;Password=Shatru123@;Encrypt=True;TrustServerCertificate=True;"
  },
  "WhatsApp": {
    "BaseUrl": "https://wa.shivkalaclasses.com",
    "ApiKey": "YOUR_LONG_RANDOM_SECRET"
  }
}

Important rules

  • YOUR_LONG_RANDOM_SECRET must be the same value as GitHub secret WHATSAPP_API_KEY.
  • The file is for the main ASP.NET site only, not the WhatsApp subsite.
  • The WhatsApp subsite uses its own web.config generated by the workflow.

5. Deployment Flow

  1. Push the latest code to the main branch.
  2. Open GitHub Actions and run the CI-CD workflow if it does not trigger automatically.
  3. Wait for these jobs to pass: build, deploy-web, and deploy-whatsapp-sidecar.
  4. Connect to SmarterASP via FTP and confirm that the main site folder site1 now contains the published application files.
  5. Edit site1/appsettings.Production.json with the production database and WhatsApp values.
  6. Restart the application pool from SmarterASP if needed.

6. Database Migration

Run the production migration once from your local machine so the hosted SQL Server gets the required schema.

dotnet ef database update --project src/Shivakala.SqlServerMigrations --startup-project src/Shivakala.Web -- --provider=SqlServer
Tip: run this only after the SQL Server connection string is final. If you rotate the password, update the connection string before running migrations again.

7. Verification Checklist

  • Open https://shivkalaclasses.com and confirm the public site loads.
  • Open https://shivkalaclasses.com/admin/login and confirm the login page loads.
  • Open https://wa.shivkalaclasses.com/status and confirm JSON is returned.
  • Log into the admin portal and open the WhatsApp page.
  • Confirm the QR area loads instead of showing a sidecar configuration warning.

8. WhatsApp Setup

  1. Open https://shivkalaclasses.com/admin/whatsapp.
  2. Wait for the QR code to appear.
  3. On the mobile phone, open WhatsApp and go to Linked Devices.
  4. Scan the QR code shown in the admin panel.
  5. Confirm the status changes to connected.
  6. Send a small test broadcast before using the feature for a real audience.

9. Troubleshooting

Main site loads but login or data fails

  • Check site1/appsettings.Production.json.
  • Confirm Database.Provider is set to SqlServer.
  • Confirm the SQL Server connection string is correct.

WhatsApp deploy fails

  • Check the GitHub Actions job named deploy-whatsapp-sidecar.
  • The workflow now trims non-runtime files before deploy, so a failure usually means hosting permission or runtime issues.

/status fails on the WhatsApp subsite

  • Check whether the Node.js app is enabled on the `wa` subsite.
  • Check whether SmarterASP supports the Chromium requirement for whatsapp-web.js.
  • If Chromium is not available, move only the sidecar to a small VPS and keep the main site on SmarterASP.

QR does not appear

  • Verify the main app and sidecar share the same WhatsApp API key.
  • Verify WhatsApp.BaseUrl points to https://wa.shivkalaclasses.com.

10. Security Notes

Rotate the SQL password. The current SQL Server password was exposed during setup chat, so it should be changed in SmarterASP and then updated everywhere it is used.
  • Use a strong random value for WHATSAPP_API_KEY.
  • Do not commit live passwords into the repository.
  • After deployment is stable, consider rotating the SmarterASP Web Deploy password too.
